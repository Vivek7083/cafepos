# CafePOS: what I have in mind

## Topic 1: what should be the flow

- The unified login approach, keep the email verification first for the first time login users(enter email, enter verification code)
- Setup password and then login, from next time only email and password, no need of verification code, forgot password then required
- Register approach
	* owners: the owners have the most critical registering step
		* enter the following details 
			- Cafe name, phone number, their name, the email, gstin
		* then after they register, we have to approve them via dashboard 
		* approved via us then in our unified login  approach, from the email we know the email belongs to the owners
	* other staff will be added by the owner on the dashboard that he has
	
- Owners
	- owners have the super admin role, they can perform crud on tables, menu, staff and all other functionality that we will providing via our platform
	- they can add managers (based on what positional hierarchy the cafe follows, some cafes owners are also managers so its fine)
	- now since the base setup is done from the owner
	- they can add staff	
		- in staff they can add predefined roles with manager, waiter, kitchen staff etc
		- they can add custom roles (phase 2)
		- they can decide the permissions that any role can have (phase 2); for now we will decide
		- enter email of the staff, enter their name and staff receives the email, receives the email for unified login
		- enters email, we check the role, and the verification code password flow and as per their role the dashboard will look like that	
- Managers
	- Can add tables, add waiters and kitchen staff and edit menu
	- only owners and managers can mark a table reservation as paid


- Waiter
	- They receive orders, they make entry on when a table is occupied by a customer (though manager and owner can do it as well)
	- they they continue with entering the user request 
	- once the customers are done with eating, they can request the waiter for the bill
	- now in phase 1 we are not handling payments, but then the waiter receives payment (in some cafes customers pay at the owner/cash counter)
	- so waiter can mark the table as service_completed and awaiting payment, manager/owner can mark the status of a table as payment_completed
	- now in some cafes, payments are made before hand and then service is done so we need to think about that as well, like once registration is done an owner can decide what they do, like we receive payments early and then serve 
	
	
- kitchen staff	
	- they see the tables and the requested items, they can add the inventory things like in notes, which managers and owners can see 
	- now is some cafes the waiters and the kitchen staff would be same so in this case multiple roles could be handled
	- owner is super role, manager has a lot of functionality other than the cafe details and the payment flow 
	- waiter attends customers and manages tables and add request, kitchen staff prepares food for the request and handles food_ready_to_serve which then waiter can see on their table thning
	- now in some cafes the kitchen staff may not be registered, so in that case waiter can mark the status as food served, now we need to handle such cases
